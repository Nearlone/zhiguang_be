# RAG 扩展语料首轮基线报告

测试时间：2026-07-16

## 测试范围

- 语料：15 篇公开知文，共 97 条 Elasticsearch 向量。
- 问题：45 道，其中事实题 15 道、机制题 15 道、文档外拒答题 15 道。
- 参数：`topK=5`、`maxTokens=1024`，逐题串行请求，每题无对话历史。
- 服务：最新版后端运行于临时 `18081`；原 `8080` 实例保持运行但未作为测试入口。
- 原始数据：[`baseline-2026-07-16.jsonl`](./results/baseline-2026-07-16.jsonl)。
- 异常复测：[`retest-2026-07-16.jsonl`](./results/retest-2026-07-16.jsonl)。

## 基线结论

首轮结果为**部分通过，尚未达到问题集规定的完整通过标准**。

| 指标 | 结果 | 判断 |
| --- | ---: | --- |
| HTTP 成功 | 44/45，97.8% | 1 道 Embedding 请求超时 |
| 可回答题首轮正常生成 | 29/30，96.7% | 1 道在索引重建后误判为空召回 |
| 成功生成回答的引用覆盖 | 29/29，100% | 全部至少有一个引用 |
| 跨文章引用 | 0 | 通过 |
| 首轮文档外题正确拒答 | 14/15，93.3% | 1 道因请求超时未返回，未达到 100% 标准 |
| 异常题复测 | 2/2 通过 | 两个异常均未稳定复现 |

人工按 6 分制检查 30 道可回答题：22 道完整覆盖标准要点，7 道覆盖主要内容但有轻微遗漏，
1 道首轮误拒答，平均约为 **5.63/6**。回答忠实度和引用正确性较好，主要缺口集中在检索稳定性与回答完整性。

## 延迟与 Token

以下服务端延迟统计不包含客户端超时且未正常结束的 `Q10-N`。

| 指标 | P50 | P95 | 最大值 |
| --- | ---: | ---: | ---: |
| 检索耗时 | 970 ms | 4,954 ms | 14,286 ms |
| 首 Token | 2,443 ms | 9,070 ms | 26,979 ms |
| 正常请求总耗时 | 3,249 ms | 9,906 ms | 27,897 ms |
| 客户端总耗时（含超时） | 3.283 s | 12.087 s | 180.003 s |

43 次模型生成取得了服务商 usage，共消耗：

- Prompt Token：53,604
- Completion Token：4,599
- Total Token：58,203

14 道成功返回的文档外题共消耗 17,222 Token，平均约 1,230 Token/题。它们均召回了 5-7 个切片，
随后依靠 Prompt 让模型拒答，并没有在检索阶段空召回。因此拒答行为正确，但仍产生了不必要的模型调用成本。

## 主要发现

### P0：融合结果超过 topK

`topK=5` 时，43 次非空召回中有 40 次返回 6 或 7 个上下文，占 93.0%。分布如下：

| 最终命中数 | 请求数 |
| ---: | ---: |
| 5 | 3 |
| 6 | 28 |
| 7 | 12 |

当前 RRF 融合后的截断数量没有遵守接口中“topK 为最终上下文数量”的语义，会增加 Prompt Token，
也使调用方无法通过参数准确控制上下文规模。

### P0：文档外问题未在检索阶段拒绝

14 道成功的文档外题都召回了上下文并调用 DeepSeek，最终统一回答“当前知文中没有足够信息回答这个问题”。
这说明 Prompt 安全约束有效，但检索相关性门槛没有阻止无关向量进入生成阶段。

后续应比较相似度阈值、两路召回最低证据条件或轻量相关性判断。阈值必须通过本题集校准，避免把真实可回答题错误拒绝。

### P0：Embedding 调用存在 180 秒长尾

`Q10-N` 首轮在查询向量阶段等待 180 秒后失败。后端日志确认：

```text
stage=retrieval
errorType=ResourceAccessException
message=DashScope embeddings Read timed out
totalMs=180026
```

客户端未收到正文或结构化 SSE 错误。该题复测在 1.961 秒内正常拒答，因此属于外部服务长尾，但当前超时上限过长，
且失败反馈不够友好。需要独立设置连接/读取超时、有限重试和统一错误事件。

### P0：重建后立即检索可能看不到新向量

`Q07-F` 首轮发现旧索引版本后自动重建 7 个切片，紧接着的检索却返回 0 条并误拒答。下一题和复测均能召回 7 条。
这符合 Elasticsearch 写入后刷新可见性的短暂窗口：重建成功不一定等于下一次搜索立即可见。

需要在“重建完成后同请求继续问答”的路径增加 refresh、等待可见或有限短轮询，避免第一次问答误拒答。

测试期间日志还出现 5 篇知文被判定为旧索引版本。由于原 `8080` 旧实例与临时最新版实例同时连接 Kafka，
不排除不同版本消费者交替写入的干扰。下一轮性能复测应只保留同一代码版本的索引消费者。

### P1：回答完整性仍有小幅空间

以下回答覆盖了主要结论，但相较标准要点存在遗漏：

| 问题 | 主要遗漏 |
| --- | --- |
| `Q02-M` | 解释了分数量纲问题，但未补充 RRF 或校准归一化方案 |
| `Q03-F` | 公式与 k 的影响正确，未提到常见默认值 60 |
| `Q04-M` | 说明精度与计算取舍，未明确量化降低内存及最终上下文限制 |
| `Q05-M` | query/document 解释正确，未提醒兼容接口需核对参数支持 |
| `Q06-F` | max_tokens 解释正确，未说明输入输出总长度仍受上下文窗口限制 |
| `Q12-M` | 顺序、幂等和重放正确，未明确位点数据需要持久化 |
| `Q15-M` | AOP 与多级缓存一致性正确，未补充失败补偿或短 TTL |

这些不是事实错误，优先级低于检索稳定性。后续可通过更精确的上下文选择、问题分解或完整性检查改善。

## 已验证能力

- 单篇知文 `postId` 隔离有效，未出现跨文章引用。
- 真实 `chunkId` 引用映射有效，未出现未知或伪造来源。
- Prompt 对 14 道成功文档外题均能稳定约束模型拒答。
- 服务商 Token usage 能够在 43 次模型调用中完整取得。
- 两道首轮异常复测后均恢复，系统具备恢复能力，但缺少更快的超时与可见性保障。

## 下一轮优化顺序

1. 让 RRF 最终结果严格遵守 `topK`。
2. 增加检索相关性门槛，减少文档外问题进入模型，同时用 30 道可回答题防止误拒答。
3. 缩短 Embedding 超时并规范检索失败的 SSE 错误响应。
4. 处理索引重建后的 Elasticsearch 可见性窗口。
5. 完成上述改动后使用同一 45 题复测，对比拒答 Token、P95、超时率和答案完整性。
