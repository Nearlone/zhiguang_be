# 倒数排名融合 RRF

> 整理来源：[Elasticsearch Reciprocal Rank Fusion](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)

## 基本思想

Reciprocal Rank Fusion，简称 RRF，用来把多个具有不同相关性指标的结果列表合并成一个最终排名。它只依赖每个结果在各自列表中的名次，不要求 BM25 分数、余弦相似度或其他分数能够直接比较。

对候选文档 `d`，RRF 分数可以表示为：

```text
score(d) = Σ 1 / (k + rank(q, d))
```

其中 `q` 表示某一条检索通道，`rank(q,d)` 从 1 开始，`k` 是排名平滑常数。如果某个文档没有出现在某条结果列表中，该列表不会为它贡献分数。

## 为什么常量 k 很重要

`k` 越小，第一名相对后续名次的优势越明显；`k` 越大，相邻排名的分差越平缓。工程中常见的默认值是 60，它可以避免单条检索通道的第一名获得过大的优势，同时仍保留排名信息。

假设切片 A 在 BM25 中排第 1、向量检索中排第 2，那么它会获得两部分分数。切片 B 只在 BM25 中排第 1，只获得一部分分数。两路都认可的 A 通常会排在只被一路找到的 B 前面。

## rank_window_size 与最终 size

融合前，每条检索通道需要提供一定数量的候选，这个窗口可以称为 `rank_window_size`。最终返回数量通常称为 `size`。候选窗口必须不小于最终数量，否则融合算法没有足够结果可以比较。

窗口过小会漏掉稍靠后但被多路共同命中的文档；窗口过大会增加检索、内存和排序成本。应通过离线评测选择窗口，而不是只凭经验无限增大。

## 去重与稳定排序

同一个切片可能同时出现在 BM25 和向量结果中。融合时必须按稳定的 `chunkId` 去重，并累计两路排名贡献，而不是把它作为两段重复上下文交给模型。

如果两个候选的 RRF 分数完全相同，还需要确定稳定的次级排序规则，例如最佳单路排名、首次出现顺序或固定文档 ID。稳定排序有助于复现实验，避免相同问题多次请求时来源顺序随机变化。

同一路结果中也可能因为历史脏数据出现重复 `chunkId`。这种重复不应多次加分，否则相当于一条检索通道重复投票，会人为放大该切片的权重。

## RRF 的边界

RRF 不理解文档内容，只融合已有排名。如果两条检索通道都没有召回关键证据，RRF 无法凭空补回。它也不能替代权限过滤、相似度阈值、Cross-Encoder 重排或答案评测。

RRF 适合作为低成本、无需训练的基础融合方法。拥有标注数据后，可以继续比较加权 RRF、语义重排和 Learning to Rank，但这些方案会增加配置和推理成本。
