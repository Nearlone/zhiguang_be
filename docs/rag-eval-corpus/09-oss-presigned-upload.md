# OSS 服务端签名直传

> 整理来源：[阿里云 OSS 服务端签名直传](https://help.aliyun.com/zh/oss/user-guide/obtain-signature-information-from-the-server-and-upload-data-to-oss)

## 为什么采用直传

传统上传先把文件发送到业务后端，再由后端转发到对象存储。大文件会占用业务服务器带宽、连接和内存。服务端签名直传由后端生成短期上传权限，浏览器直接把文件发送到 OSS，业务后端只负责鉴权、策略和结果确认。

直传不意味着前端获得永久 AccessKey。后端使用自己的凭证计算预签名 URL 或签名表单，把允许的对象路径、请求方法、Content-Type、文件大小和过期时间限制在授权中。

## 完整上传链路

1. 前端调用后端创建文章草稿，获得字符串形式的 `postId`。
2. 前端携带 `postId`、上传场景、扩展名和 Content-Type 请求预签名信息。
3. 后端校验草稿所有者和文件类型，生成受控的 `objectKey` 与短期 PUT URL。
4. 前端使用预签名 URL 直接上传 Markdown 或图片到 OSS。
5. 上传成功后读取 ETag，并计算文件大小和 SHA-256。
6. 前端调用内容确认接口，把 `objectKey`、ETag、大小和摘要写入数据库。
7. 元数据完整后再发布文章，异步创建 RAG 索引。

## Content-Type 必须一致

签名时包含的请求头必须与实际上传请求一致。浏览器自动添加或修改 `Content-Type`，而签名中没有包含相同值时，OSS 可能返回 403 SignatureDoesNotMatch。

后端不能只相信文件扩展名或前端 `accept` 属性。应建立 MIME 与扩展名白名单，例如 `text/markdown` 只允许 `.md` 或 `.markdown`，图片场景只允许 JPEG、PNG 和 WebP 等明确类型。

## objectKey 与权限

对象路径应由后端生成，不能让前端任意指定。例如正文固定为 `posts/{postId}/content.md`，图片使用文章目录、日期和随机文件名。生成签名前还要校验当前用户确实拥有该草稿。

签名有效期应尽量短。使用 STS 临时凭证时，即使预签名 URL 设置了更长过期时间，URL 也不能超过 STS 凭证自身有效期。

## 上传确认与发布事务

预签名成功不代表文件已经上传，前端收到 PUT 200 也不代表数据库已经记录内容。内容确认接口建立 OSS 对象与文章记录之间的关联。

发布前应检查标题、正文地址、大小和摘要等必要字段。向量写入失败时，需要把失败状态返回前端或标记为可重试，不能悄悄发布一个永远无法问答的文章。

SHA-256 可以判断正文内容是否变化，ETag 可以保存对象存储返回的版本信息。二者一起使用，有助于避免内容未变化时重复生成向量，也能检测文章更新后是否需要清理旧索引。
